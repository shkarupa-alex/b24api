# Обходы, позиционные вызовы и доказательство завершения

> Нормативная часть утверждённого дизайна. Охват: #3, #5; аудит 4, 6–8; сценарии #6/1, 6, 7, 11–14.

## Архитектура и инвариант

Сохранить ОО границу `contracts/` и механик. `PageStride` отвечает только за продвижение wire control, `ClosureRule` — за квалифицированное доказательство конца, `CompletionGate` — единственный конструктор сильного терминального отчёта. Замороженные публичные value objects имеют по одной ответственности. Ядро не содержит имён Bitrix методов и не знает прикладной БД. Методные факты живут в версионированных профилях/registry.

Каждый traversal family регистрирует поддерживаемые события gate. Gate учитывает все admitted bindings, scheduled pages, delivery/acknowledgement, negative/unknown/not-executed outcomes, page rejection, caller stop, early close и cleanup failure. `COMPLETED` разрешён лишь когда каждый binding учтён, число выданных страниц совпало с acknowledged, нет отрицательных/неизвестных/неисполненных исходов и есть квалифицированный witness для заявленной assurance. Неподключённая семья не может выдать `COMPLETED`. `COMPLETED_WITH_FAILURES` никогда не имеет operation-wide `exhausted=true`; `exhausted` требует естественного исчерпания всех bindings. Отчёт агрегирует ограниченный объём evidence, не бесконечный список страниц. Structural проверки возможны скользящим окном; они сами по себе не доказывают snapshot при изменении данных. Тест архитектуры запрещает обход gate при terminal report construction; positive-control fixtures для каждого вида отрицательного события проверяют проводку.

## Caller stop, checkpoint и resume (#3)

Публичный page-boundary stop policy возвращает `CONTINUE` либо `CALLER_STOP(reason)` по immutable странице и binding. Он вызывается после проверки страницы, перед следующим schedule; исключение policy — failure. Поддержка требуется cursor, обычному offset, keyset и reference traversals, где binding можно безопасно вывести из очереди. Counted physical batched tail отвергает stop при construction; отдельный direct-tail может его поддержать. `PageAdapter` не меняет cardinality, порядок и IDs ради остановки. `CALLER_STOP` даёт только bounded-prefix assurance и не означает source exhaustion. Для `im.dialog.messages.get` пример останавливает конкретный chat после целой страницы ниже cutoff; соседи продолжают.

Page-boundary event служит durable acknowledgement seam: приложение commit'ит строки и checkpoint до запроса следующей страницы. При resume клиент перечитывает ограниченный overlap, прикладное keyed storage подавляет дубли, overlap identity сверяется в конечном budget. Gate различает глобальный `EARLY_CLOSED`, per-binding stop, failure, unknown и exhausted. Не выдавать checkpoint как полный после incomplete/unknown.

## Stride и closure (аудит 6–8)

`OffsetSpec` раздельно описывает server page granularity, requested wire limit, максимальное decoded rows и wire increment. LIVE: `crm.requisitelink.list` и `tasks.task.list` округляют `start` вниз до 50: 25/49 повторяют 0, 932 повторяет 900, 950 продвигает. Несовместимые stride/limit отвергаются до I/O; полноценная страница проверяется на ширину. Для one-based page index (`socialnetwork.workgroup.getgridpopupmembers`, `getlistincomingusers`) increment равен 1, max rows может быть 10: fixture `page=1,2,3` и `10/3/0` строк. Конец требует квалифицированной closure, не арифметики page index.

Sparse offset `im.search.user`: выбранный mapping может быть пустым посередине raw SQL диапазона. Только квалифицированный raw total и стабильный SQL order позволяют продолжать `0,50,100` через `visible,empty,visible`; `next` и selected count не определяют следующий offset. Если total отсутствует, меняется, отрицателен или не доказан как raw bound, сильный completion запрещён; конечный budget предотвращает бесконечный обход. Mutable offset source без snapshot evidence имеет ослабленную assurance. `crm.timeline.comment.list` игнорирует `>ID`, поэтому keyset по нему запрещён до иной квалификации.

Counted tail проверяет **каждый** scheduled offset/window, exact total, identities, duplicate page signature и delivery; два sampled pages не подтверждают весь хвост. Предыдущее 582 direct / 400 batch для `crm.requisitelink.list` — историческая гипотеза без доступной frozen fixture. LIVE при `entityTypeId=2` на тестовом портале 437/437 direct/batch с шагом 50; поздний unfiltered total=812 относится к другой выборке. При доступности исходного >400 fixture сравнить первый расходящийся raw offset; если нужен direct tail, сделать его явным публичным dispatch без скрытого переиздания уже выданных строк. Composite identity `(entityTypeId,entityId)` обязателен.

## Cursor domain и keyset (#5)

`CursorSpec` задаёт exclusive range predicate либо opaque token и запрещённые/игнорируемые значения. LIVE `im.dialog.messages.get`: `LAST_ID` означает `id < c`; положительная несуществующая граница допустима, `0`/null игнорируются и перезапускают head, negative/non-numeric дают typed error. `LAST_ID=1 -> []` — корректное исчерпание диапазона ниже 1. Игнорируемое значение reject до dispatch или при progression. `FIRST_ID` теряет середину и не допускается как traversal control. Положительный probe `c+1` для этого range не нужен и может дать ложный отказ после удаления; opaque token получает отдельный positive control только по доказанной неоднозначности.

Экономия последнего keyset вызова допускается лишь при квалифицированном верхнем bound для того же filter, реально enforced fence и принятом **точном** boundary ID. Отдельный probe row не является witness. При отсутствии условия остаётся empty confirmation или слабый/incomplete report. Проверить sequential, auto, fast по отдельности и reject неподдерживаемый режим до I/O.

## Positional ABI (аудит 4)

`PositionalArguments`/slot layout владеет точным числом и порядком top-level слотов; имя ключа не заменяет позицию. Транзакционный writer меняет существующий control slot, допускает создание leaf только внутри существующего nested container, сохраняет фиксированные predicates, отвергает near-match casing и overlap, проверяет фактические encoded bytes. LIVE `task.elapseditem.getlist` принимает четыре не scoped слота `order,filter,select,params` и пять task-scoped `taskId,order,filter,select,params`; оба дают HTTP 200, но разные totals. Сценарий 13 требует пять слотов и semantic scope oracle. Текущий form encoder теряет пустые слоты, что может молча изменить scope: positional form и physical batch fail preflight до отдельного byte+portal доказательства; начальная поддержка direct JSON. `task.commentitem.getlist`, `task.items.getlist`, `task.item.getlist` квалифицируются независимо. HTTP 200 и проверка байт без проверки scope недостаточны.

## Исполнимый контракт gate и памяти

Публичная схема `CompletionEvent` — tagged immutable union с `operation_id`, `binding_id`, `page_id` и монотонным `sequence`: `BindingAdmitted`, `PageScheduled`, `CommandOutcome(SUCCESS|FAILURE|UNKNOWN|NOT_EXECUTED)`, `PageValidated(identity_digest, row_count)`, `PageDelivered`, `PageAcknowledged`, `PageRejected`, `BindingTerminal(SOURCE_EMPTY|QUALIFIED_TOTAL|BOUNDARY_SEEN|CALLER_STOP|FAILURE|UNKNOWN)`, `StreamTerminal(NATURAL|EARLY_CLOSE|CANCELLED)`, `CleanupOutcome(SUCCESS|FAILURE)`. Для страницы порядок `Scheduled→CommandOutcome(SUCCESS)→Validated→Delivered→Acknowledged`; `PageRejected` завершает её отрицательно и запрещает delivery; `PageAcknowledged` означает, что consumer принял всю страницу и завершил durable commit callback, если он предоставлен. Повторный/неизвестный `page_id`, событие после terminal и пропущенный predecessor — blocking protocol violation. Для каждого admitted binding ровно один terminal. Gate не принимает новое событие после stream terminal, кроме cleanup.

`CompletionGate.finish()` возвращает frozen `OperationReport` только после cleanup. `COMPLETED` требует stream `NATURAL`, cleanup success, ни одного blocking violation/negative/unknown/not-executed, равенства scheduled→settled→validated→delivered→acknowledged для выданных страниц и terminal каждого binding с квалифицированным witness. `CALLER_STOP` разрешает `COMPLETED` операции с bounded-prefix assurance, но `exhausted=false`. `COMPLETED_WITH_FAILURES` означает, что все bindings учтены, некоторые failed/unknown, и всегда `exhausted=false`, `partial=true`. `INCOMPLETE` — неопределённый outcome, incomplete delivery/cleanup/early close или недоказанная closure. `OperationReport.exhausted` становится отдельным frozen полем, вычисленным gate как `all(binding_terminal == SOURCE_EMPTY or qualified full-source equivalent)`, при отсутствии отрицательных исходов; `partial = not successful or not exhausted`. Так `COMPLETED` с bounded stop успешен, но частичен по источнику. Любое старое construction report в обход gate запрещается статическим тестом и удаляется из drivers.

Gate хранит O(active bindings + in-flight pages) корреляцию и ограниченный trace (default 128 записей, ошибки имеют приоритет). Exact duplicate identity на произвольно отсортированном полном наборе **не** обещается в такой памяти. Для сильной `IDENTITY_EXACT` требуется либо квалифицированный строго монотонный order с проверкой соседних окон и уникальности внутри страницы, либо публичный `IdentityStore` с `add_if_absent(key) -> bool`, bounded chunk writes и внешним backing store. Для counted tail exact total и покрытие offset интервалов проверяются interval ledger O(number of windows) или внешним ledger, а не путём хранения всех rows в отчёте. При превышении настроенного `max_windows` операция даёт `INCOMPLETE/BUDGET`, не сужает проверку выборкой. Uninstrumented family регистрирует поддерживаемые events до dispatch; если обязательный event не реализован, preflight отказ.

`PageStopPolicy.on_page(PageBoundary) -> CONTINUE | CALLER_STOP(reason)` получает immutable correlation, page rows и validated control; callback выполняется после `PageDelivered`, завершает durable commit и только затем допускает `PageAcknowledged`, до schedule следующей страницы. Исключение — failure, reason — непустая безопасная строка до 128 символов. Counted physical batch tail с policy отвергается при construction. `SparseRawBound(total_path, stride, max_pages, order_contract)` — отдельный explicit closure rule, не глобальная замена `OffsetContinuation`. При неверном/изменившемся raw total и повторной странице — blocking violation. `PageIndex(initial=1, increment=1, max_rows=10, control_path=...)` задаёт wire index независимо от decoded cap.

Для #5 `BoundedIdentityRange(filter_fingerprint, upper_id, lower_exclusive, order, fence_path, source_version)` фиксируется до traversal. Верхний fence включён в каждый wire filter и проверяется по каждой принятой строке; witness — exact `upper_id` в admitted странице, а не в отдельном probe. При новых ID выше fence результат говорит только о диапазоне `id <= upper_id`; snapshot всего текущего источника не заявляется. Удаления/изменения внутри диапазона без snapshot или changelog не позволяют `IDENTITY_EXACT` по source population, даже если boundary встретился; допустим только `BOUNDED_RANGE_OBSERVED` и требование overlap/reconciliation. Если метод не гарантирует order/fence, оптимизацию отключить и использовать empty confirmation с соответствующей слабой assurance.
